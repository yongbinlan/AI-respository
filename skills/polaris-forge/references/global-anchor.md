# 可选的全局启用

本文件供获得明确配置修改授权后的 Agent 使用；普通任务不自动执行这一配置流程。Skill 按需发现和全局指令加载是两个环节，安装文件不保证每次调用或结果质量。

## 合并步骤

1. 根据宿主当前配置和适用说明定位用户级指令文件、实际安装的 `polaris-forge/SKILL.md` 及有效覆盖文件。使用当前机器已确认的完整路径，不复制他人的用户名、目录或个人规则；遵守该环境的 Skill 隔离约定。
2. 读取现有规则及优先级。若有效覆盖文件、配置冲突、共享/链接路径或权限使作用范围不确定，先报告具体情况；不另写一个可能不会加载的文件冒充生效。
3. 检查是否已经有同等入口。有等效入口则不重复追加；替换旧入口时先核对它的独有要求和已有调用，保留有效约束，不批量覆盖其他规则。
4. 保存可恢复的旧版本，生成仅涉及本 Skill 入口的差异。将下方区块中的说明改为当前环境已核实的实际安装位置，再在已授权范围内合并；原文件在此期间发生变化则重新检查后再写。
5. 回读差异、验证实际 Skill 路径和引用；在宿主中检查新入口是否被加载。未观察到加载时只报告配置已写入，说明下一步核验方法。

备份可能包含个人或业务信息，仅留在本地，不随本公开包上传。移除时只处理本 Skill 的受管区块，不删除其他规则或用户成果。

## 可合并区块

以下示例使用技能名称定位；正式合并前，在入口句中注明当前环境已验证的实际安装路径，不把这个示例当作运行时已经配置的证据。

```markdown
<!-- polaris-forge:start -->
## 北辰·成果引擎：项目协作入口

- 实质性创作、实施、策划、修复和项目维护开始前，读取已安装的 polaris-forge/SKILL.md，统一理解目标、补充需求、按复杂度执行并验证成果；专业 Skill 与项目正式门禁继续有效。
- 先利用现有证据，主动给出有依据的完善建议；仅对实质影响成果、保留内容、费用或权限的未决项提问。明确、简单的任务直接处理。
- 需求变化、失败和关键阶段转换时复核受影响部分；交付前检查实际结果，修复并复验可检测的问题。不得把安装、语法通过或内部评分当作真实效果证明。
- 老项目维护覆盖已授权范围与真实问题。后台定时执行须有明确请求，不因本规则自动扫描其他项目或修改长期记忆。
- 多个通用方法 Skill 共享同一工作理解，避免重复流程。入口缺失或不可读取时说明缺口，不声称 Skill 已运行。
<!-- polaris-forge:end -->
```

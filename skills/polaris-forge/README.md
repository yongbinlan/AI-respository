# 北辰·成果引擎

Polaris Forge

给 Codex 一个需求，它会先弄清你要交付什么，发现遗漏时补上建议，做完后检查实际结果。适用于编程、内容、设计、研究和已有项目的维护。

## 安装后就能这样用

把下面这句发给具备 `skill-installer` 的 Codex：

```text
使用 $skill-installer 安装 https://github.com/yongbinlan/AI-respository/tree/main/skills/polaris-forge
```

手动安装和安装后的检查见[仓库首页](../../README.md#安装)。

接着带上你的需求：

```text
使用 $polaris-forge 帮我做一个一键生成 PFP 头像的 Skill。
先看看需求里还缺什么，提出值得做的改进，再开始制作。
```

比如这个例子，需要先弄清照片怎么输入、最终交付头像还是全身图、什么程度的相似度可以接受。多种画风、适配尺寸、批量生成可以作为建议提出；新增功能是否值得做，要看目标和成本，不能把产品设想当成已经验证的消费者需求。

简单、明确的任务直接处理。已有上下文能回答的问题不会再问；只有答案会影响结果、必须保留的内容、费用或权限时，才需要你决定。后续成本高、方向又不确定的任务，可以先做一个小样。

## 做完以后检查什么

检查随交付物而变：代码要跑到修改过的行为，页面要打开看、操作一下，文档要核对内容和排版。发现问题先修，再检查受影响的部分。交付时说明查过什么、还有什么没验证。

专业 Skill 负责具体制作，原有项目的验收要求继续执行。北辰本身是一套工作方法，没有额外运行库、API Key、遥测服务或后台进程。

## 检查一个旧项目

```text
使用 $polaris-forge 检查当前项目，先只读。
找出有效版本、重复出现的问题和卡住的步骤，给出证据与修改建议。
```

它会核对旧测试对应的时间、版本和环境，再判断结论能否继续使用。有真实问题才提出修复，没有发现就如实结束。

这条指令只做检查。要修改时可以继续指定范围；需要长期定时维护，则另行确定项目、频率、允许修改的内容和通知条件。

## 想在其他任务里也用

安装后可以用 `$polaris-forge` 明确调用。包里的 `agents/openai.yaml` 也允许 Codex 按任务选择它，实际是否加载取决于宿主。

如果希望加入全局工作规则，按[全局启用说明](references/global-anchor.md)授权 Codex 检查现有配置、备份并合并入口。普通安装不会修改全局规则。

已有 `goal-alignment-guard`、`creative-task-router` 或 `top-thinking` 时，可以授权把旧调用整合到北辰；安装本包不会自动替换它们，也不依赖它们运行。

## 效果与限制

北辰的目标是帮助减少遗漏和重复返工，实际改善仍需在项目里观察。安装成功、内部评分或情景模拟都不能证明用户满意，也不能保证零错误或每次都超预期。模拟试用应标为 `SIMULATED`，与真实反馈和效率数据分开记录。

付费、发布、账户、安全和破坏性操作仍需要相应授权。

完整执行规则见 [SKILL.md](SKILL.md)；需要了解检查方法时，可读[验收与自审](references/verification.md)和[项目维护](references/maintenance.md)。
